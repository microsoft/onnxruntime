# Padded small-M SIMT: preserved prototype and full-model A100 evaluation

Measured 2026-10-22 on A100-SXM4-80GB, NVIDIA Vulkan, driver 580.159.04.
Batch 1, FP16 activations, INT4 block32, Qwen 3.8 27B, genuine DFlash2
width-specific exports. This follows the historical isolated results in
[RESULTS.md](RESULTS.md); those older automatic-path timings are not this
experiment's baseline.

## Decision

**Keep developing this targeted opt-in, but do not enable it by default.**
The full-target M=4 run reproduces 1.666x MLP projection speedup, 1.260x total
GPU speedup, and 1.284x clean completed-host speedup at context 1500.
Width-3 generation improves 1.089x on short and 1.144x on long versus its
matched existing routing. Short width-3 is 1.133x ordinary autoregressive
baseline; long width-3 is still 9.2% slower than that baseline.
Long generated sequences change, so these are not token-equivalent quality
results or evidence for automatic production selection.

## Actual opt-in routing

Unset or `ORT_WEBGPU_EXPERIMENTAL_SMALL_M_SIMT=0` preserves existing selection.
`=1` admits only M=2/4/8, `(K,N)=(5120,17408)` or `(17408,5120)`,
FP16/INT4/block32/accuracy4, one weight batch, and no bias, explicit zero
points, weight selection, or activation-row replay. All other shapes, including
N=1024 and N=10240, keep their original paths.

The integrated configuration is fixed: 128 threads, BN8, BK512, one padded
`vec4<f16>` per staged block32, and BM=M. It has one dispatch, 2176 gate/up
workgroups or 640 down workgroups, and 3328/6656/13312 shared bytes for M=2/4/8.
There is no prepack or separate reduction. Diagnostic tuning environment
variables do not alter this route.

Each enabled controlled forward actually executes **192 `DiagnosticSmallMSimt`
dispatches: 64 gate, 64 up, and 64 down**. Cache keys confirm
`BM|8|512|4|1`, including the padded layout. Disabled forwards execute zero.
M=2/4 baseline MLP projections are regular `MatMulNBits`; at M=8 the baseline
gate/up use `SubgroupMatrixMatMulNBits` plus their layout dispatches, while
down remains regular. Total target dispatches are:

| M | Existing | Experimental |
|---|---:|---:|
| 2 | 1204 | 1204 |
| 4 | 1205 | 1205 |
| 8 | 1333 | 1205 |

**The genuine drafter is not routed in these experiments.** Although its
five layers have the same MLP dimensions, their omitted `accuracy_level`
resolves to the schema default 0, not the target's explicit 4. Native profiles
show only target-session SIMT dispatches; drafter MLPs remain regular.
The allowlist is based on shapes/types/attributes, not fragile fused-node names.

The long width-3 routing smoke dispatches both `ConvStateReplay` and
`GatedDeltaNetStateReplay` 48 times with either routing setting. Separate
node assignment profiles contain no heavy CPU fallback; the remaining CPU
operations are the existing shape/selector metadata operations. The target
alone has only CPU `Unsqueeze`.

## Controlled target verification

Both settings use the same loaded session and identical plugin/core libraries.
All 128 state tensors are restored before every call from immutable snapshots
at contexts 100 and 1500. Inputs are the same eight consecutive tokens from the
established baseline sequence, using prefixes of length M. This M=8 replay is
not the earlier isolated test's repeated M=4 activation.

State reset and auxiliary hidden-state readback are outside completed-host
timing. Logit readback fences actual completion; enqueue time alone is not
reported as completed latency. Each condition has eight alternating warmups.
GPU campaigns have five repetitions, clean host campaigns ten. Order reverses
each repetition. Every repeated logit and auxiliary output is finite and
bitwise deterministic within its condition.

## Full-generation results

Short is **86 prompt -> 128 generated tokens**; long is **1315 -> 512**.
All conditions use identical tokenized prompts, greedy deterministic generation,
no repetition penalty, no prefix cache, and no graph capture. The minimum
generated-token floor stays zero so genuine draft verification remains active.
Baseline explicitly disables the drafter. Widths 1/3 use genuine two-/four-row
production exports, not a shared eight-row graph with a runtime-width override.

Each condition has one full-length warmup and five measured repetitions.
Off/on conditions alternate within the same loaded sessions; condition order
reverses each repetition. No native GPU, node, compiler-statistics, or host
attribution profiling is active during these headline measurements. Timings
cover `begin_turn` through terminal Engine events, including prefill and
decoding, but exclude model loading, Engine/request creation, and request cleanup.
All 60 measured sequences and speculative counters exactly reproduce their
own full-length warmup. There are no speculative failures, disables, admission
misses, or standard-fallback steps.

Medians in seconds; speedups are ratios of medians. "Matched" compares the same
width/export with routing off/on. "vs baseline" compares against ordinary
autoregressive baseline with the same routing setting.

|---|---|---:|---:|---:|---:|---:|

## Scope and portability

Production defaults remain off. This is not a production rollout or a claim
of equivalent tokens/quality across different accumulation paths.
The original 56-shader pinned-Tint WGSL/MSL validation is preserved in
[RESULTS.md](RESULTS.md). The relocated generator emits the same portable
f16 SIMT shader without subgroup requirements, freshly revalidated above.
No Apple SDK compilation,
Apple hardware correctness, or M4/M5 performance measurement was performed.
